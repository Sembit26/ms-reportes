# Modos de Falla — MS Reportes

> Borrador inicial (Hito 0). Se completará con los modos de falla del contrato simulado en Hito 1 y de la lógica real en Hito 2.

| Modo de falla                               | Causa / Escenario                                                                                        | Qué la impide (Mitigación)                                                                                                                                                                  | Cómo se verifica                                                            |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------- |
| **Configuración obligatoria faltante**      | Falta una variable de entorno obligatoria (`API_PORT`, `API_ENV`, `DATABASE_URL`, `FRONTEND_URL`, `TZ`). | Validación estricta al arranque de `cmd/api` que termina el proceso con error explícito si falta una variable obligatoria.                                                                  | Prueba de arranque sin variable requerida y verificación en logs.           |
| **PostgreSQL no disponible**                | La base de datos aún no responde o cayó durante la operación.                                            | `migrate` espera `service_healthy` de `postgres`; `backend` espera `service_completed_successfully` de `migrate`; `GET /readyz` ejecuta `Ping` real a PostgreSQL y devuelve `503` si falla. | Prueba de `GET /readyz` con PostgreSQL activo y caído.                      |
| **Formato de salida inválido**              | Solicitud de reporte con formato distinto a `pdf` o `xlsx`.                                              | Validación en el contrato OpenAPI/Huma y error controlado en `internal/service`.                                                                                                            | Pruebas unitarias en `internal/service` y pruebas de endpoint/E2E.          |
| **Proveedor externo caído o lento (G2/G3)** | MS Gestor de Información o MS Plantillas no responde o excede el timeout.                                | Clientes HTTP con timeout explícito de `5s` por defecto y respuesta de error controlada en formato RFC 9457.                                                                                | Pruebas contra mocks (Prism/MSW en Hito 1) y servidor mock en E2E (Hito 2). |
